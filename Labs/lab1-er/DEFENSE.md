# Defense: Завдання 1 — ER-модель онлайн-бібліотеки з підпискою

## 1. Намір і критерії

Онлайн-бібліотека з підпискою: користувач оформлює підписку на тариф, читає
книги каталогу, накопичує прогрес і залишає відгуки. Модель описує ці дані як
12 сутностей із зв'язками й кардинальностями — вона стане основою для Lab2-Lab5.

Критерії прийняття зафіксовані в [spec.md](spec.md), розділ «Критерії
прийняття»: типізовані `string` ідентифікатори, явний PK у кожної сутності,
3НФ, чистий M:N для книги й жанру, асоціативна сутність для книги й автора,
збіг назв атрибутів між spec і моделлю, збіг рендера з джерелом.

## 2. Топ-3 розбіжності (знайдені й виправлені)

Деталі — в [AUDIT.md](AUDIT.md).

1. **Складені обмеження унікальності описані в spec, але не виражені в моделі** —
   проти spec, розділ «Сутності та атрибути» (`Review`, `ReadingProgress`).
   Модель допускала два відгуки одного користувача на одну книгу.
   → Commit: `lab1: fix - add composite unique keys for review and progress`

2. **Похідні атрибути збережені як поля** — `ReadingProgress.percent` і
   `Loan.status` обчислюються з інших даних, збереження дає змогу суперечливим
   станам. → Commit: `lab1: fix - drop derived attributes from progress and loan`

3. **Неправильна кардинальність самозв'язку `Genre`** — `||--o{` вимагав батька
   в кожного жанру, тоді як кореневі жанри його не мають.
   → Commit: `lab1: fix - genre parent cardinality allows root genres`

Усі три виправлені через зміну `spec.md` і критеріїв, а не ручним патчем
діаграми.

## 3. Ключове рішення

Два зв'язки «багато-до-багатьох» змодельовані **по-різному**:

- книга — жанр — чистий M:N, бо зв'язок не несе власних атрибутів;
- книга — автор — асоціативна сутність `BookAuthor`, бо зв'язок несе `role`
  (автор / перекладач / ілюстратор) і `ordinal` (порядок на обкладинці).

Розглядав три варіанти для книги й автора: чистий M:N (не дозволяє зберегти
роль), асоціативна сутність (обрано), окремі сутності під кожну роль
(роздуває модель). Для книги й жанру розглядав чистий M:N і сутність
`BookGenre` — друге відкинув як порожню обгортку.

→ [adr/adr-002-book-author-associative.md](adr/adr-002-book-author-associative.md)
→ [adr/adr-001-notation.md](adr/adr-001-notation.md) — вибір Mermaid замість
PlantUML: рендер нативно в GitHub, і на машині немає Java.

## 4. Перевірка узгодженості

Для першого завдання попередньої моделі немає, тому перевіряв узгодженість
**spec ↔ модель**:

- звірив назви всіх атрибутів у `spec.md` і `model/er.mmd` — розбіжностей немає;
- звірив кардинальності з таблицею зв'язків у `spec.md` — саме тут знайшов
  розбіжність #3;
- перевірив, що кожна сутність зі spec присутня в моделі й навпаки — 12 з 12;
- перевірив, що кожна сутність має хоча б один зв'язок — «висячих» немає;
- перевірив, що жодне обмеження з spec не залишилось невираженим — тут знайшов
  розбіжність #1.

Цей ланцюг перевірок стане шаблоном для Lab2-Lab5, де додасться звірка з
попередніми моделями.
