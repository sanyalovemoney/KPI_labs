# Lab1 — ER-модель: онлайн-бібліотека з підпискою

## Домен

Онлайн-бібліотека з підпискою — сервіс, у якому користувач оформлює платний
доступ на певний строк і читає книги з каталогу.

Домен обрано самостійно, єдиного кодового проєкту-джерела немає: концепцію змодельовано на основі категорії підписних книжкових платформ (модель Bookmate).

## Що є в предметній області

**Користувач і доступ.** Людина реєструється, обирає тариф (Plan) і оформлює
підписку (Subscription) на певний строк. Підписка оплачується — кожен платіж
фіксується окремо (Payment), бо за строк підписки платежів може бути кілька, і
кожен має власний статус (успішний, відхилений, повернений).

**Каталог.** Книга (Book) належить видавництву (Publisher) і має одного або
більше авторів (Author). Книга належить до кількох жанрів (Genre) — це чистий
зв'язок «багато-до-багатьох» без власних атрибутів. Жанри утворюють ієрархію
(«Фантастика» -> «Космічна фантастика»).

**Читання.** Користувач бере книгу (Loan), читає її та накопичує прогрес
(ReadingProgress). Після прочитання може залишити відгук з оцінкою (Review).

## Чому цей домен

Домен обрано самостійно (зовнішнього проєкту-джерела немає) як узагальнення категорії книжкових платформ за моделлю Bookmate, тому модель спирається на реальну бізнес-практику підписних сервісів, а не на абстрактний приклад.

Причини вибору саме цього домену для курсу:

1. **Природне моделювання обов'язкових патернів даних**:
   - **Чистий M:N** — книга належить кільком жанрам, жанр містить багато книг. Власних атрибутів у зв'язку немає, тому окремої сутності не треба.
   - **Асоціативна сутність** — зв'язок «книга — автор» (`BookAuthor`) несе власні атрибути (роль: автор / перекладач / ілюстратор, і порядок у списку авторів). Тут окрема сутність виправдана.
   - **Ієрархія сутностей** — деревоподібний зв'язок батьківських і дочірніх жанрів.
2. **Наскрізність для ланцюга робіт**: домен містить зовнішню систему-актора (платіжний шлюз) — вона потрібна для Lab2 (Use Cases) та Lab3 (Sequence Diagram), тривалі бізнес-процеси (підписка, читання, прогрес) для Lab4 та зовнішні інтеграції для Lab5.
3. **Реалістичність і цілісність**: охоплює повноцінний життєвий цикл взаємодії користувача з сервісом (каталог, тарифи, підписка, трекінг прогресу читання, відгуки) без штучних сутностей чи надмірного ускладнення.
