# Defense: Завдання 4. Процес «Оформлення підписки»

## 1. Намір і критерії

Lab3 показала кроки по чотирьох сценаріях; lab4 зшиває їх в один процес —
паралельність, розгалуження і повідомлення. Форма — activity PlantUML зі
swimlanes за ролями.

Критерії зафіксував у [spec.md](spec.md): рівно одна форма, ≥1 розгалуження,
fork/join на реальній синхронізації, send signal + accept event з продовженням
без очікування, повідомлення дослівно з sequence Lab3, без недосяжних кроків,
рендер синхронний з джерелом.

Деталі в [AUDIT.md](AUDIT.md), розділ «Цикл lab4».

   UML join чекає ВСІ гілки; супереч ADR-001 lab3). Виправлення: два

   → Commit: `ee13ea5` lab4: модель

## 3. Ключове рішення

Дві точки входу процесу: запуск читачем (Потік A) і callback-подія (Потік B).
Дубль-транзакція (REQ-05) — повторний callback без дії читача, тому вона не
може жити всередині лінійного потоку від `submitSubscription`. Шлюз — тригер
зовнішньої події, а не виконавець: він приймає send signal `authorizePayment` і
надсилає accept event `onGatewayCallback`, але власної доріжки не має — його
внутрішня обробка списання не наша. Fork на повідомленнях успіху
(`returnPaymentId` | `subscriptionActivated` → `showResult`) — свідома абстракція
порядку: у sequence вони послідовні, але залежності за даними немає, тож у
процесі паралельні. Async — продовження ADR-001 lab3.

→ [ADR-001 (lab3)](../lab3-sequence/adr/adr-001-gateway-callback-recipient.md):
callback приймає Сервіс платежів;
[ADR-001 (lab4)](adr/adr-001-gateway-as-event-trigger.md): шлюз — тригер, не
виконавець.

## 4. Перевірка узгодженості

Повідомлення процесу звірив дослівно з sequence Lab3 (seq-01..04): ті самі
назви й напрями. Числа — з Gherkin Lab2: 49900, "UAH", "gw-8842", "pay-01",
30 днів. Учасників звірив з `er.mmd`: Сервіс підписок (`Subscription`, `Plan`),
Сервіс платежів (`Payment`), Читач (`User`); шлюз зовнішній. PNG звірив очима
проти `.puml`: маркери «•» видні, fork/join на місці, чотири доріжки. Недосяжних
кроків немає: кожен шлях (REQ-04, REQ-05, відмова, успіх) веде до кінця; дубль
входить у Потік B без дії читача. Пошти немає (ADR-002 lab2).
