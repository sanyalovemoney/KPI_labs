# ADR-001: Платіжний шлюз — тригер події, не виконавець (без доріжки)

## Статус

Прийнято. Узгоджено зі `spec.md` («Ролі», «Форма (і чому)»),
`model/subscription-process.puml` і AUDIT (знахідка 1).

## Контекст

Activity-діаграма має swimlanes за ролями. Учасників п'ятеро з Lab3: Читач,
Веб-UI, Сервіс підписок, Сервіс платежів, Платіжний шлюз. Але шлюз — зовнішня
система: він приймає `authorizePayment` і надсилає callback, та внутрішню
обробку списання виконує не наша система. Треба вирішити, чи давати шлюзу
власну доріжку з кроками.

## Decision Drivers

- Межа системи: ми моделюємо свій процес, а не внутрішність зовнішнього шлюзу.
- Шлюз лише ініціює подію (callback) і приймає сигнали — він не виконує кроків
  нашого процесу.
- Дубль-транзакція (REQ-05) — повторний callback без дії читача: має бути
  досяжна без запуску потоку читачем.
- Узгодженість з ADR-001 lab3: callback асинхронний, приймає Сервіс платежів.

## Розглянуті варіанти

1. **Дати шлюзу власну доріжку з кроком «обробити списання».**
   Плюс: видно всі п'ять ролей як доріжки. Мінус: показує внутрішню обробку
   зовнішньої системи, якої ми не моделюємо; розмиває межу; «обробити списання»
   — не наш крок і не має сутності в `er.mmd`.
2. **Шлюз — тригер події (send signal / accept event), без доріжки.**
   Плюс: межа чесна; callback = окрема точка входу (Потік B); дубль досяжний
   без читача. Мінус: доріжок чотири, а ролей п'ять — треба пояснення в spec.
3. **Шлюз як note/анотація без сигналів.**
   Мінус: не видно напрямків `authorizePayment` / `returnPaymentId` / callback.

## Рішення

Варіант 2. Шлюз — зовнішній тригер: `authorizePayment` іде до нього як send
signal, `onGatewayCallback` приходить від нього як accept event (окрема точка
входу, Потік B), `returnPaymentId` повертається йому. Власної доріжки шлюз не
має: кроків нашого процесу він не виконує.

## Наслідки

- На activity чотири swimlanes: Читач, Веб-UI, Сервіс підписок, Сервіс платежів.
- Процес має дві точки входу: запуск читачем (Потік A) і callback-подія
  (Потік B); дубль (REQ-05) входить у Потік B без дії читача.
- Асинхронне вікно = send signal + detach + accept event, без fork; fork/join
  лишається на успішному шляху — окрема абстракція (spec «Форма (і чому)»).
- Якщо шлюз заміниться на іншого провайдера, діаграма не змінюється по суті:
  це питання Lab5.
