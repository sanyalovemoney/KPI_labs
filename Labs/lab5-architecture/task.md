# Завдання 5 — Architecture

Умова від викладача (скопійовано з RULES.md).

## Мета

Модель архітектури — компоненти, інтерфейси, залежності й межі системи.

## Артефакт (текст + рендер)

UML Component Diagram у декларативному синтаксисі (PlantUML component /
Mermaid) — компоненти (UI, API/Backend, сервіси, Data Access, БД),
provided/required-інтерфейси, залежності, чітка межа системи, зовнішні
інтеграції (Payment, SMS/Email, OAuth/Identity, External API…). Рендер —
компонентна діаграма з цього опису.

## Що зробити

- spec.md: модулі (UI, API, сервіси, Data Access, БД) + зовнішні інтеграції.
- Побудувати компонентну модель; згенерувати діаграму.
- Аудит: кожен компонент/залежність трасується до попередніх моделей (дані,
  вимоги, взаємодія, процес); межа системи чітка; provided/required-інтерфейси
  визначені; топ-3 розбіжності.
- DEFENSE.md: як модель інтегрує весь ланцюг моделей.

## Ознаки відмінного виконання

компоненти, інтерфейси й межі коректні; повна узгодженість з моделлю даних,
вимогами, взаємодією та процесом; аудит присутній.
