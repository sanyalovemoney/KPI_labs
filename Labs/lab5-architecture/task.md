# Завдання 5 — UML Component Diagram

Умова від викладача (повна версія DoD).

## Мета

Модель архітектури — компоненти, інтерфейси, залежності й межі системи.

## Артефакт (текст + рендер)

UML Component Diagram у декларативному синтаксисі (PlantUML component /
Mermaid) — компоненти (UI, API/Backend, сервіси, Data Access, БД),
provided/required-інтерфейси, залежності, чітка межа системи, зовнішні
інтеграції (Payment, SMS/Email, OAuth/Identity, External API…).
Рендер — компонентна діаграма.

## Що зробити

- `spec.md`: модулі (UI, API, сервіси, Data Access, БД) + зовнішні
  інтеграції.
- Побудувати компонентну модель; згенерувати діаграму.
- Аудит: кожен компонент/залежність трасується до попередніх моделей
  (дані, вимоги, взаємодія, процес); межа системи чітка;
  provided/required-інтерфейси визначені; топ-3 розбіжності.
- `DEFENSE.md`: як модель інтегрує весь ланцюг моделей, що узгоджено.

## Ознаки відмінного виконання

- компоненти, інтерфейси й межі коректні;
- повна узгодженість з моделлю даних, вимогами, взаємодією та процесом;
- аудит присутній.

## Якщо з AI

AI не є джерелом вимог і рішень — йому ставиться задача аналізу й дозбору
(знайти прогалини, поставити уточнювальні питання, запропонувати варіанти),
а формулює й вирішує студент; `spec.md` і `DEFENSE.md` — власноруч (DoD §1).

## Здача — 2 входи

- Посилання на GitHub PR.
- DEFENSE — заповнений шаблон або власний `DEFENSE.md`.
